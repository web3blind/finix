# Publication status — experimental beta

This status supersedes older release-gate prose where it describes the default
feature as disabled. The reviewed runtime enables the guarded default feature;
this documentation change does not alter runtime gates or role checks.

## Verified Linux local milestone

The exact reviewed native package completed physical-default recovery on an
isolated synthetic Linux real-default root. One fresh preparation and one Apply
reached a new READY owner. The actual stock session picker returned three original
sessions, stock history returned six original messages, the saved note was
restored, and SQLite integrity was `ok`. Old-only memories and skills were removed;
shared resources and sibling data remained unchanged. The existing encrypted
backup was reused without recapture or a package-manager clone. This is genuine
local workflow evidence, not merely archive verification or a named-profile test.

Durable bounded preparation is implemented in the registered CLI and shipped
Desktop protocol, including exact-job polling, cancellation intent and uncertain
acknowledgement reconciliation. The matched client and backend ship together.
Preparation does not authorize Apply: fresh root/plan/epoch-bound consent and
native ownership checks remain required. Interrupted legacy operations remain
blocked. Never discard retained state or repeat Apply to recover a lost indicator.

## Reviewed POSIX CURRENT source admission

CURRENT code now requires trusted source ownership, no non-owner write permission
on source files or package directories, and retained no-follow ancestry while reading bounded regular
files. Hardlinks with no non-owner write permission remain compatible;
non-owner-writable inodes and unsafe
ancestry are refused. The guard and its focused tests were independently reviewed
and exercised on native Linux, including cross-user write attempts, root-owned
code compatibility and bounded descriptor use. Native Windows regression tests
preserve its unchanged admission branch; skipped POSIX cases prove no Windows
POSIX protection.

This is a separately tested source-boundary increment, not a second full Apply.
The Linux functional workflow above used the earlier reviewed native package,
without this guard; its unchanged functional evidence is retained, not relabelled
as a new end-to-end run. This is not whole-plugin security certification.

  Protocol/component tests and Linux success do not prove that workflow.

  or AI-turn-readiness claim follows from these results. The accepted cooperative
  same-OS-user target condition in README still applies; it is not atomic defense
  against hostile concurrent target replacement. Keep independent backups.

## Risk disclosure

Finix reads selected Hermes profile content outside its own plugin directory and
creates encrypted archives and private recovery staging. Restore may replace
profile content only through explicit consent and reviewed ownership checks.
External age/age-keygen processes are required; optional rclone/Google Drive
integration makes third-party network calls when explicitly configured. Scheduling
and recovery jobs can run in the background. Recovery keys are sensitive: keep
private keys outside the backup host. Google sign-in is through Hermes-managed
OAuth; no vendor credential files are included. No SDK, password manager, demo
data, evidence bundles or private recovery material is included in this source.
Telemetry is not enabled by this publication. Review setup and safety documents.
